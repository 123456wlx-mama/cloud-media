# MediaPlayer 视频播放器 · 项目技术说明

> 配套文档：[README.md](../README.md)（功能 / 编译运行 / 亮点 / 常见问题）
> 本文面向**想看懂代码、想改代码**的人：线程模型、同步原理、seek 流程、音频链路、生命周期与排错。

---

## 1. 总体架构

```
┌──────────────── 界面线程（Qt main thread）────────────────┐
│ PlayerDialog：打开/播放/暂停/停止、进度条、音量、地址栏     │
│ GLVideoWidget（QOpenGLWidget）：纹理渲染                   │
└─────── 信号（SIG_getOneImage / SIG_TotalTime / 状态变化）──┘
                        ▲ 信号槽（跨线程，QImage 已深拷贝）
┌──────────────── VideoPlayer（继承 QThread）───────────────┐
│ run() = 【读线程】：av_read_frame → 音频包/视频包分别入队  │
│                     同时负责 seek、流量控制、资源回收       │
└───────────────────────────────────────────────────────┘
        │ SDL_CreateThread                    │ SDL_OpenAudioDevice
        ▼                                     ▼
┌ video_thread（SDL 线程）────────┐   ┌ audio_callback（SDL 音频线程）──┐
│ 取视频包 → 解码 → YUV→RGB32     │   │ 取音频包 → 解码 → 重采样 → 混音 │
│ → 音视频同步（等音频时钟）      │   │ → 更新 audio_clock（主时钟）    │
│ → QImage → 抛信号给界面         │   │                                 │
└────────────────────────────────┘   └────────────────────────────────┘
        ▲                                     ▲
        │                                     │
   PacketQueue videoq                   PacketQueue audioq
   （SDL mutex + cond，带 quit/abort/flush）
```

**为什么这样分**：
- 读线程（Qt 线程）只做 IO，不做解码，避免解码耗时拖慢读包；
- 视频解码单独线程，音频交给 SDL 的音频回调线程（音频必须按设备时钟准时喂数据，放回调里最稳）；
- 三者通过 `PacketQueue` 解耦，队列自带锁与条件变量。

## 2. 核心数据结构

### 2.1 `VideoState`（`videoplayer.h`）—— 全局播放状态

| 分组 | 成员 | 说明 |
|---|---|---|
| 容器 | `pFormatCtx` | `AVFormatContext`，相当于"视频文件指针" |
| 音频 | `audio_st / audioStream / pAudioCodecCtx / audioq` | 音频流、索引、解码器、包队列 |
| 音频 | `audio_clock` | **主时钟**（微秒），由音频包的 pts 换算 |
| 音频 | `audioID / audio_fmt / out_frame` | SDL 设备 ID、设备实际采样格式、重采样输出参数 |
| 音频 | `audio_buf / audio_buf_size / audio_buf_index` | 解码后的音频缓冲与读游标 |
| 视频 | `video_st / videoStream / pCodecCtx / videoq` | 视频流、索引、解码器、包队列 |
| 视频 | `video_clock / video_tid` | 视频时钟（补偿用）、视频解码线程句柄 |
| 控制 | `isPause / quit` | 暂停标志、退出请求（所有线程共用的"总闸"） |
| 控制 | `readFinished / readThreadFinished / videoThreadFinished` | 读包结束 / 读线程结束 / 视频线程结束 |
| seek | `seek_req / seek_pos / seek_time / seek_flag_audio / seek_flag_video` | 跳转请求（微秒）、目标时间、音/视频"跳过中间帧"标志 |
| 其他 | `volume / start_time / m_player` | 音量 0~128、无音轨时的系统时钟基准、回指播放器（用于抛信号） |

> **坑点记录**：`VideoState` 含非 POD 成员，不能用 `memset` 清零，因此用**构造函数初始化列表**逐项初始化；
> `run()` 每轮播放开始都会 `m_videoState = VideoState();` 重置一次。

### 2.2 `PacketQueue`（`PacketQueue.h/.cpp`）—— 线程安全包队列

| API | 作用 |
|---|---|
| `packet_queue_init` | 初始化（创建 mutex / cond） |
| `packet_queue_put` | 入队（拷贝一个 packet 引用，加锁） |
| `packet_queue_get(q, pkt, block)` | 出队；`block=0` 非阻塞（**解码线程必须非阻塞，否则退不出**） |
| `packet_queue_abort` | 唤醒并终止阻塞中的 get（停止/结束时用） |
| `packet_queue_flush` | 清空剩余包，队列仍可用（seek 用） |
| `packet_queue_destroy` | 释放剩余包 + 销毁锁 |

`size` 统计的是**包内数据总字节数**，不是包个数——流量控制按它判断。

### 2.3 `VideoPlayer` 对外接口

| 方法 | 说明 |
|---|---|
| `setFileName(path)` | 设置文件/URL 并 `start()` 起线程 |
| `play() / pause()` | 清/置 `isPause`；暂停时音频回调输出静音 |
| `stop(isWait=true)` | 置 `quit`、`abort` 队列、可选等待读线程退出 |
| `seek(pos)` | 请求跳转（微秒） |
| `getCurrentTime() / getTotalTime()` | 当前播放时间 / 总时长（微秒） |
| `setVolume(v)` | 音量 0~128 |
| `getPlayerState()` | `Playing / Pause / Stop` |
| 信号 | `SIG_getOneImage(QImage)`、`SIG_PlayerStateChanged(int)`、`SIG_TotalTime(qint64)` |

## 3. 音视频同步

**策略：音频时钟为主时钟（audio master）。**

1. 音频回调每取到一个音频包就更新主时钟：

```cpp
is->audio_clock = (double)pkt.pts * av_q2d(is->audio_st->time_base) * 1000000.0; // 微秒
```

2. 视频线程拿到的帧 pts 换算成 `video_pts`（微秒），若 **视频超前于音频**就延时等待：

```cpp
while (video_pts > audio_pts) { SDL_Delay(5); ... }   // 最多等 500ms 防异常卡死
```

3. `synchronize_video()` 做**帧延时补偿**：用流的 `time_base` 计算帧间隔，并叠加重复帧
   `repeat_pict * frame_delay * 0.5`，持续推进 `video_clock`，保证无 pts 的帧也能正确节奏播放。

4. **无音轨时**退化为**系统时钟同步**：以 `start_time = av_gettime() - video_pts` 为基准，
   循环等待到该帧的显示时刻再渲染。

> 为什么选音频做主时钟：人对声音的卡顿最敏感；音频由设备时钟驱动、采样率恒定，
> 比"用系统时间估算"更稳，视频只要跟着音频走即可。

## 4. 跳转（seek）流程

```
界面点击进度条 → VideoSlider::SIG_valueChanged
    → PlayerDialog 节流（QElapsedTimer，避免 HLS 高频请求）
    → VideoPlayer::seek(pos)：置 seek_req = 1，seek_pos = pos（微秒）

读线程循环里检测 seek_req：
    1) av_seek_frame(pFormatCtx, stream_index, 目标 ts, AVSEEK_FLAG_BACKWARD)  // 退到前一个关键帧
    2) packet_queue_flush(audioq / videoq)  清空两个队列
    3) 向两个队列各放入一个 FLUSH 包（内容 "FLUSH"）
    4) video_clock = 0                 // 关键：不清零，向左跳转会一直等旧音频时钟
    5) seek_flag_audio = seek_flag_video = 1，seek_time = 目标时间

音频侧：取到 FLUSH → avcodec_flush_buffers(pAudioCodecCtx)，丢弃缓存；
        之后 audio_clock < seek_time 的包直接丢弃（跳过中间帧）。
视频侧：取到 FLUSH → avcodec_flush_buffers(pCodecCtx)，video_clock 清零；
        解码出的帧 pts < seek_time 的直接丢弃，直到追上目标时间再显示 → 不花屏。
```

`AVSEEK_FLAG_BACKWARD` + "跳到目标时间戳"两步走，兼顾了**只能从关键帧开始解码**的限制与**用户看到的跳转精度**。

## 5. 音频链路

```
SDL_OpenAudioDevice(期望参数: 源采样率/声道/AUDIO_S16SYS)
        │  SDL 返回实际参数（audio_fmt 保存下来）
        ▼
audio_callback(userdata, stream, len)        // SDL 音频线程周期性调用
   ├─ 暂停 → memset(stream, 0, len) 输出静音
   └─ while(len > 0):
        ├─ 缓冲空 → audio_decode_frame()
        │     ├─ packet_queue_get（非阻塞）
        │     ├─ FLUSH 包 → avcodec_flush_buffers
        │     ├─ 更新 audio_clock（主时钟）
        │     ├─ avcodec_decode_audio4() 解码（一个包可能含多帧）
        │     └─ SwrContext 重采样到设备格式（声道/采样率/采样格式）
        └─ SDL_MixAudioFormat(stream, buf, audio_fmt, len1, volume)  // 混音 + 音量
```

- 音频缓冲 `audio_buf` 大小 `(AVCODEC_MAX_AUDIO_FRAME_SIZE * 3) / 2`（1 秒 48kHz 32bit 的 1.5 倍）；
- 解码失败/无数据时填充静音，保证设备不断流；
- 音量由 `SDL_MixAudioFormat` 最后一参控制（0~`SDL_MIX_MAXVOLUME`=128），无需改数据本身。

## 6. 视频解码与渲染

```
videoq 取包
  → avcodec_decode_video2()                // FFmpeg 4.2 的解码接口
  → best_effort_timestamp → video_pts（微秒）
  → synchronize_video() 补偿
  → 音视频同步等待（见第 3 节）
  → sws_scale()：YUV → RGB32（SWS_BICUBIC）
  → QImage(out_buffer, w, h, Format_RGB32).copy()   // 必须深拷贝，缓冲会被复用
  → SendGetOneImage(img) → 信号 → 界面 GLVideoWidget::setImage()
```

`GLVideoWidget`（`glrender/`）：

| 步骤 | 说明 |
|---|---|
| `initializeGL()` | 编译顶点/片段着色器、创建纹理与 VBO |
| `setImage()` | 保存当前帧（统一转 RGBA8888），触发 `update()` |
| `uploadTexture()` | 把帧数据上传为纹理 |
| `updateVertex()` | 按控件尺寸**等比缩放并居中**，计算顶点/纹理坐标 |
| `paintGL()` | 绑定纹理、绘制；`clearShow()` 时画黑屏 |

相比原方案（`QLabel` + `QImage::scaled`）：GPU 采样缩放画质更好、CPU 占用更低，且窗口可自由伸缩。

## 7. 网络流支持（RTMP / HLS）

| 处理 | 代码位置 | 说明 |
|---|---|---|
| 启用网络协议 | `avformat_network_init()` | 不调用则打不开 `rtmp://`、`http://` |
| 打开超时保护 | `interrupt_open_cb()` + `NetOpenCtx` | TCP 连接不可达会**永久阻塞**；设置回调后：连上则不再打断、**超过 5 秒**判定超时、点停止立即打断 |
| 读包容错 | `av_read_frame < 0` 计数 | 网络抖动不立即退出，连续 300 次失败才认为读结束 |
| 队列非空即等待 | `video_thread` 中 | 读得慢时解码线程只 `SDL_Delay(1)` 等待，不退出 |
| 拖动节流 | `PlayerDialog::m_lastSeek` | HLS 拖动会触发大量分片请求，过密的直接忽略 |

打开路径统一用 **`toUtf8()`**：FFmpeg 在 Windows 下要求 UTF-8，而 `toStdString()` 是本地编码（GBK），中文路径会打不开。

## 8. 生命周期与资源回收

**启动**：`setFileName()` → `start()` → `run()` 中依次
`av_register_all()` → `avformat_network_init()` → `SDL_Init()` → 打开输入 → 查流 → 开解码器 → 建队列 → 起视频线程 → 开音频设备 → 进入读循环。

**结束（正常播放完 / 点停止）**，严格按序，否则崩溃：

1. 置 `quit = 1`；`packet_queue_abort()` 唤醒阻塞的解码线程；
2. 等待 `videoThreadFinished`（**先停解码线程，再释放解码器**）；
3. `SDL_PauseAudioDevice(1)` + `SDL_CloseAudioDevice()`（在 `SDL_LockAudio()` 保护下）；
4. `packet_queue_flush` + `destroy` + `delete` 两个队列；
5. `avcodec_close()` 音频/视频解码器 → `avformat_close_input()` → `av_packet_unref/av_free`；
6. 线程内 `SDL_Quit()`，置 `readThreadFinished = 1`，抛 `SIG_PlayerStateChanged(Stop)`。

停止时若上一轮的 `quit` 还没被消费，新一轮 `run()` 直接返回，防止状态被冲掉。
`stop(isWait)` 可等待读线程退出后再继续，避免"停止后马上打开下一个文件"导致资源竞争。

| 常量 | 值 | 含义 |
|---|---|---|

## 11. 调试与排错

| 手段 | 说明 |
|---|---|
| 日志文件 | `main.cpp` 用 `qInstallMessageHandler` 把 `qDebug` 写到 **`D:/mediaplayer/player_debug.log`** |
| Qt Creator | 用 Qt Creator 启动即可在"应用程序输出"看实时日志 |
| 典型日志 | `can't open file:`（打不开）、`Couldn't find stream index`、`Codec not found.`、`Couldn't init SDL`、`VideoPlayer::run end` |

| 故障 | 排查方向 |
|---|---|
| 一打开就崩 | 多为 DLL 缺失或 32/64 位不匹配；先看日志与 DLL 是否齐全 |
| 停止时崩 | 线程回收顺序：`abort → 等 videoThreadFinished → 关音频 → 关解码器 → 关输入` |
| 播放几秒卡住 | 队列阈值/网络流；看 `readFinished`、`DelayCount` 相关日志 |
| seek 后花屏 | 检查 FLUSH 包是否两侧都放、`video_clock` 是否清零 |
| 音画不同步 | 检查 `audio_clock` 是否更新（无音轨时走系统时钟分支） |
| 画面不刷新 | `QImage` 必须 `.copy()` 深拷贝后再跨线程传递，否则缓冲被复用导致花屏/黑屏 |

## 13. 扩展指引

| 想加的功能 | 改哪里 |
|---|---|
| 播放列表 / 下一个文件 | `PlayerDialog` 维护列表；切换时 `stop(true)` → `setFileName()` |
| 倍速播放 | 需要重采样/丢帧或改用 `avfilter` 的 `atempo`，并同步调整时钟 |
| 截图保存 | `GLVideoWidget::setImage()` 里保存当前 `QImage` |
| 硬解码 | 替换 `avcodec_find_decoder` 为指定 hwaccel（DXVA2/CUDA），注意像素格式需回读 |
| 字幕 | 用 `libass` 或 `avfilter subtitles` 滤镜，在 `sws_scale` 之后叠加到 QImage |
| 替换新 FFmpeg | 注意 API 变化：本项目用的是 `avcodec_decode_video2/audio4`、`avpicture_get_size` 等**旧接口**（4.2 仍可用但有 deprecated 警告）；升级到 5.x 需改 `avcodec_send_packet/receive_frame` |
