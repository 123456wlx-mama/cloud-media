## 1. 项目概述

本项目是一个**功能完整的私有云网盘**，从零实现，不依赖任何网盘 SDK：

- **客户端**：Qt 图形界面，提供登录注册、文件浏览、上传下载、分享等完整交互；
- **服务端**：C++ 手写 TCP 服务器，Linux 版采用 `epoll` + 线程池支撑并发；
- **数据库**：服务端用 MySQL 存用户与文件元数据，客户端用 SQLite 缓存断点续传任务；
- **协议**：自定义二进制协议（协议号 + 定长结构体 + 柔性数组），TCP 长连接。

核心亮点功能：**秒传（MD5 去重）**、**上传/下载断点续传与暂停恢复**、**文件夹递归上传/下载**、**分享码分享**、**引用计数文件管理**。

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│                     Qt 客户端 client/NetDesk                   │
│                                                              │
│   LoginDialog ──┐                                            │
│   MainDialog ───┼──► CKernel（单例，业务核心）                  │
│                 │      ├─ 协议映射表 PFUN[100]                 │
│                 │      ├─ m_mapTimestampToFileInfo（传输任务）  │
│                 │      └─ CSqlite（database/<userid>.db）      │
│                 └──► netapi：INetMediator ──► INet(TcpClient)  │
└───────────────────────────┬──────────────────────────────────┘
                            │  TCP 私有二进制协议（默认端口 8004）
                            ▼
┌──────────────────────────────────────────────────────────────┐
│              主服务端 server/linux-epoll（Ubuntu）              │
│                                                              │
│   main.cpp ─► TcpKernel（单例）                                │
│                 ├─ Block_Epoll_Net（epoll LT + ONESHOT）       │
│                 │     └─ thread_pool（10~200 线程，队列 50000）  │
│                 ├─ 协议映射表 PFUN[100] → CLogic（业务）        │
│                 └─ CMysql（libmysqlclient）                    │
│                                                              │
│   磁盘存储根目录：/home/colin/NetDisk/<userid>/...              │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
                  MySQL 数据库 NetDisk
        t_user / t_file / t_user_file / 视图 user_file_info
                  触发器 refPlusOne / refMinusOne
```

**分层思想**：网络层与业务层通过**中介者模式**解耦；业务层通过**协议映射表（类成员函数指针数组）**分发，避免超长 `switch/if`。

> 另有 `server/qt-server`（Qt 控制台版服务端），复用客户端的 `netapi/sqlapi`，用 SQLite 存用户，功能较简单，主要用于对照学习，见[第 8 节](#8-备选服务端qt-控制台说明)。

## 5. 通信协议设计

### 5.1 帧格式与粘包处理

TCP 是字节流，会粘包。项目采用**长度前缀**方案，每次 `send` 把「包长」和「数据包」一次性写入：

```
+--------------+---------------------------+
|  4 字节长度   |   协议结构体（含4字节type） |
+--------------+---------------------------+
|<-- nlen ---->|<-------- nlen 字节 ------->|
```

- **发送**（客户端 `TcpClient::SendData` / 服务端 `Block_Epoll_Net::SendData`）：先写 `int nlen`，再 memcpy 数据，一次 `send` 发出。
- **接收**：先 `recv` 4 字节得到 `nPackSize`，再循环 `recv` 直到收满 `nPackSize` 字节（处理半包），最后交给上层。

### 5.2 协议号总表（`packdef.h`）

基址 `_DEF_PACK_BASE = 10000`，可寻址 100 个协议（`_DEF_PACK_COUNT = 100`）。
请求/响应成对出现（RQ = Request，RS = Response）。

| 协议号 | 宏 | 结构体 | 方向 | 说明 |
|---|---|---|---|---|
| 10000 | `_DEF_PACK_REGISTER_RQ` | `STRU_REGISTER_RQ` | C→S | 注册请求（tel / name / password-MD5） |
| 10001 | `_DEF_PACK_REGISTER_RS` | `STRU_REGISTER_RS` | S→C | 注册结果（0 手机号已存在 / 1 昵称已存在 / 2 成功） |
| 10002 | `_DEF_PACK_LOGIN_RQ` | `STRU_LOGIN_RQ` | C→S | 登录请求 |
| 10003 | `_DEF_PACK_LOGIN_RS` | `STRU_LOGIN_RS` | S→C | 登录结果（0 手机号不存在 / 1 密码错 / 2 成功，含 userid、nickname） |
| 10004 | `_DEF_PACK_UPLOAD_FILE_RQ` | `STRU_UPLOAD_FILE_RQ` | C→S | 上传文件请求（fileName/dir/size/md5/type/time/timestamp） |
| 10005 | `_DEF_PACK_UPLOAD_FILE_RS` | `STRU_UPLOAD_FILE_RS` | S→C | 上传应答（返回全局 fileid） |

### 5.3 协议结构体设计约定

- 所有结构体**第一个字段固定为 `PackType type`**（4 字节协议号），接收端据此查表分发。
- 结构体内 `char` 数组定长（如 `_MAX_PATH_SIZE=260`、`_MAX_SIZE=40`），保证收发两端内存布局一致；构造函数负责 `memset` 清零。
- 变长数据用**柔性数组**：`int fileidArray[]`、`STRU_FILE_INFO fileInfo[]`、`STRU_MY_SHARE_FILE items[]`；
  发送时 `malloc(sizeof(头) + count * sizeof(元素))`，接收端按 `count` 解析后 `free`。
- 缓冲区常量：`_DEF_BUFFER=4096`（文件块大小）、`_DEF_CONTENT_SIZE=1024`。

> ⚠️ 客户端 `netapi/net/packdef.h` 与服务端 `include/packdef.h` 是**两份拷贝**，修改协议时必须同步更新两端，否则解析错位。

## 6. 客户端功能与实现

### 6.1 界面结构

- **LoginDialog**：登录页 + 注册页（`QStackedWidget` 切换），发出 `SIG_loginCommit(tel,password)` / `SIG_registerCommit(tel,password,name)`。
- **MainDialog**：三个分页
  - 文件页：路径导航 + `QTableWidget` 文件列表 + 右键菜单（新建文件夹 / 上传文件 / 上传文件夹 / 下载 / 分享 / 删除 / 获取分享 / 收藏）；
  - 传输页：上传表格（`table_upload`）、下载表格（`table_download`），右键可「暂停 / 开始 / 全部暂停 / 全部开始」；
  - 分享页：我的分享列表（名称 / 大小 / 时间 / 分享码）。

### 6.2 功能 ↔ 实现对照

| 功能 | 客户端入口 | 发送协议 | 响应处理 |
|---|---|---|---|
| 注册 | `CKernel::slot_registerCommit` | `REGISTER_RQ` | `slot_dealRegisterRs` → 弹提示 |
| 登录 | `CKernel::slot_loginCommit` | `LOGIN_RQ` | `slot_dealLoginRs` → 隐藏登录框、显示主窗口、拉取文件列表与分享、初始化 SQLite |
| 刷新目录 | `slot_changeDir` / `slot_getCurDirFileList` | `GET_FILE_INFO_RQ` | `slot_dealGetFileInfoRs` → 重建表格 |
| 新建文件夹 | `slot_addFolder` | `ADD_FOLDER_RQ` | `slot_dealAddFolderRs` → 刷新 |
| 上传文件 | `slot_uploadFile` | `UPLOAD_FILE_RQ` | `slot_dealUploadFileRs` → 记录 fileid，发第一个 `FILE_CONTENT_RQ` |
| 上传文件夹 | `slot_uploadFolder` | 递归 `ADD_FOLDER_RQ` + `UPLOAD_FILE_RQ` | 同上 |
| 数据块循环 | — | `FILE_CONTENT_RQ` | `slot_dealFileContentRs` → 更新进度，继续读下一块直到 `pos >= size` |
| 秒传 | 上传前算 MD5 随请求发出 | 服务端回 `QUICK_UPLOAD_RS` | `slot_dealQuickUploadRs` → 直接标记完成 |
| 下载文件 | `slot_downloadFile` | `DOWNLOAD_FILE_RQ` | 服务端回 `FILE_HEADER_RQ` → `slot_dealFileHeaderRq` 建文件并发 `FILE_HEADER_RS`，之后收 `FILE_CONTENT_RQ` 落盘 |
| 下载文件夹 | `slot_downloadFolder` | `DOWNLOAD_FOLDER_RQ` | 服务端递归回 `FOLDER_HEADER_RQ` + `FILE_HEADER_RQ` |
| 上传续传 | 暂停后点「开始」 | `CONTINUE_UPLOAD_RQ` | `slot_dealContinueUploadRs` → `fseek` 到 pos 继续发块 |
| 下载续传 | 暂停后点「开始」 | `CONTINUE_DOWNLOAD_RQ` | 服务端 `lseek` 后直接回第一个数据块 |
| 分享 | `slot_shareFile` | `SHARE_FILE_RQ` | `slot_dealShareFileRs` → 刷新分享列表 |
| 获取分享 | `slot_getShareByLink` | `GET_SHARE_RQ` | `slot_dealGetShareRs` → 刷新目录 |
| 删除 | `slot_deleteFile` | `DELETE_FILE_RQ` | `slot_dealDeleteFileRs` → 刷新 |

### 6.3 关键实现细节

- **单例核心**：`CKernel::GetInstance()` 使用函数内 `static` 局部对象（C++11 线程安全），构造时完成：设协议映射表 → 读 ini → 建本地目录 → 建中介者 → 连服务器 → 建登录/主窗口并连接信号。
- **协议分发**：`PFUN m_netPackMap[_DEF_PACK_COUNT]`，`NetMap(协议号)` 宏按 `协议号 - _DEF_PACK_BASE` 取下标；收到数据后在 `slot_dealClientData` 中 `(this->*pf)(...)` 调用对应槽。
- **任务标识 timestamp**：`QDateTime::currentDateTime().toString("hhmmsszzz").toInt()`（时+分+秒+毫秒，如 143025123），作为一次传输任务的唯一 ID，并做「已存在则 +1」的冲突检测。
- **上传状态机**：`m_mapTimestampToFileInfo`（`map<int, FileInfo>`）保存任务上下文（`FILE* pFile`、`pos`、`isPause`、`size`）。
  收到数据块应答 → `pos += len` → 未传完则继续 `fread` 4KB 发送；传完则关文件、删任务缓存、刷新列表。
- **暂停/恢复**：
  - 任务在内存 map 中：直接把 `isPause` 置 1/0（发送/接收循环里 `while(info.isPause)` 空转 + `processEvents`）；
  - 任务已丢失（客户端重启）：从 SQLite 读回任务，打开文件后走 `CONTINUE_*` 协议向服务端要偏移量。
- **中文路径**：Qt 的 `QString` 是 UTF-8，`fopen` 在 Windows 需要 GB2312，因此有 `Utf8ToGB2312()` + `QTextCodec` 转换再 `fopen`。
- **密码加盐 MD5**：`getMD5(val)` = `MD5("val_1234")`（盐值 `MD5_KEY "1234"`，定义在 `ckernel.cpp`）。
- **本地落盘目录**：exe 同级 `NetDisk/`（`CKernel::setSystemPath`），下载时按协议里的 `dir` 逐级 `mkdir`。
- **配置文件**：exe 同级 `config.ini`，`[net] ip / port`，缺省 `192.168.0.23:8004`（`loadIniFile`，不存在会自动生成）。

## 7. 主服务端（Linux epoll）功能与实现

### 7.1 启动流程

```
main(argv[1]=port, 默认8000)
  └─ TcpKernel::GetInstance()->Open(port)
        ├─ initRand()            随机数种子（分享码）
        ├─ new CMysql → ConnectMysql(NetDisk@localhost, root/335566)
        ├─ new Block_Epoll_Net → InitNet(port, &TcpKernel::DealData)
        │     ├─ InitThreadPool()：Pool_create(200, 10, 50000)
        │     ├─ socket / setsockopt(REUSEADDR) / setNonBlockFd / bind / listen(128)
        │     └─ epoll_create + 监听套接字入树（EPOLLIN, LT）
        ├─ new CLogic(this)
        └─ setNetPackMap()：填充 100 项函数指针表
  └─ EventLoop()：epoll_wait 死循环
```

### 7.2 网络层并发模型

```
epoll_wait 返回事件
 ├─ 监听 fd 就绪 → accept_event()
 │     ├─ accept 得到 clientfd
 │     ├─ 设 SO_RCVBUF/SO_SNDBUF、TCP_NODELAY
 │     └─ 新建 myevent_s，注册 EPOLLIN | EPOLLONESHOT
 └─ 客户端 fd 就绪 → recv_event(ev)
       └─ 投递任务到线程池 → recv_task()
             ├─ 读 4 字节包长 → 循环 recv 收满整包（处理半包）
             ├─ 重新注册 EPOLLONESHOT（保证同一连接串行）
             └─ 投递 DataBuffer → Buffer_Deal()
                   ├─ 回调 m_recv_callback = TcpKernel::DealData
                   └─ delete[] buf; delete buffer（内存回收）
TcpKernel::DealData：type → NetPackMap(type) → (m_logic->*pf)(clientfd, buf, nlen)
```

- **LT + EPOLLONESHOT**：单次触发后需重新注册，避免多线程同时处理同一连接；
- **接收与处理分离**：`recv_task` 只负责收包，业务丢给线程池其他线程，避免业务阻塞接收；
- **线程池**：环形队列 + `not_empty/not_full` 条件变量；管理者线程每 10 秒检查，负载高（队列积压或忙碌率 ≥80%）时扩容，空闲时收缩（等待数设为 10）；
- **MyMap<K,V>**：模板化线程安全 map（`find/insert/erase/IsExist` 内部 `pthread_mutex` 保护）。

### 7.3 业务层 `CLogic` 处理函数

| 函数 | 处理内容 |
|---|---|
| `RegisterRq` | 查 `t_user` 手机号/昵称是否重复 → 插入用户 → 为用户创建磁盘根目录 `/home/colin/NetDisk/<id>/` |
| `LoginRq` | 校验手机号与密码 → 成功则写 `m_mapIDToUserInfo`（userid → UserInfo{name, clientfd}） |
| `UploadFileRq` | ① 先按 `f_MD5` 且 `f_state=1` 查 `t_file`，**命中即秒传**（插入 `t_user_file` 关系 + 回 `QUICK_UPLOAD_RS`）；② 未命中则 `open(O_CREAT|O_WRONLY|O_TRUNC)` 建文件、写 `t_file`(state=0)、写 `t_user_file`、回 `UPLOAD_FILE_RS`（带 fileid） |
| `FileContentRq` | 按 `userid*1000000000+timestamp` 取 `FileInfo` → `write` 落盘 → 累计 `pos` → 传完则关闭 fd、更新 `f_state=1`、清理 map |
| `GetFileInfoRq` | 查视图 `user_file_info`（`f_state=1`）→ 组柔性数组回复 |
| `DownloadFileRq` | 查视图取文件路径 → `open(O_RDONLY)` → 存 map → 回 `FILE_HEADER_RQ` |
| `DownloadFolderRq` / `DownloadFolder` / `DownloadFile` | **递归下载**：先回 `FOLDER_HEADER_RQ` 让客户端建目录，再查子项，文件走 `DownloadFile`、文件夹递归；timestamp 引用传递自增保证 key 唯一 |
| `FileHeaderRs` / `FileContentRs` | 下载数据块循环：读 4KB → 发 `FILE_CONTENT_RQ`；收到应答累计 `pos`，传完清理 |
| `AddFolderRq` | 写 `t_file`(type=folder) + `t_user_file` → `mkdir` → 回结果 |
| `DeleteFileRq` → `DeleteOneItem` → `DeleteFile` / `DeleteFolder` | 删除 `t_user_file` 关系（触发器减引用计数）→ 若 `t_file` 已无记录则 `unlink` 磁盘文件；文件夹递归删除 |
| `ShareFileRq` | 随机生成 9 位分享码（首位 1~9，`random()`，查重）→ 批量 `ShareItem` 写入 `s_link` / `s_linkTime` |
| `MyShareRq` | 查 `user_file_info` 中 `s_link is not null` 的记录 → 组柔性数组回复 |
| `GetShareRq` → `GetShareByFile` / `GetShareByFolder` | 按分享码查文件 → 把分享者的文件"挂"到获取者目录（写 `t_user_file`，文件夹递归） |
| `ContinueDownloadRq` | 取/建 `FileInfo` → `lseek(fd, pos, SEEK_SET)` → 直接回第一个数据块 |
| `ContinueUploadRq` | 取/建 `FileInfo` → `lseek(fd, 0, SEEK_END)` 得到已上传位置 → 回 `CONTINUE_UPLOAD_RS{pos}` |

### 7.4 服务端磁盘存储规则

```
/home/colin/NetDisk/            ← DEF_PATH（clogic.cpp 中硬编码）
   └── <userid>/                 ← 每个用户的网盘根目录（注册时创建）
        └── <dir>/<md5>          ← 文件以 MD5 命名存储（天然去重）
        └── <dir>/<folderName>/  ← 文件夹
```

以 MD5 作为落盘文件名，是"同一内容全服只存一份"的物理保证。

**触发器（引用计数自动维护）**

```sql
-- 插入用户-文件关系 → +1
CREATE TRIGGER refPlusOne AFTER INSERT ON t_user_file FOR EACH ROW
BEGIN UPDATE t_file SET f_count = f_count + 1 WHERE t_file.f_id = NEW.f_id; END;

-- 删除用户-文件关系 → -1；减到 0 即物理删除 t_file 记录
CREATE TRIGGER refMinusOne AFTER DELETE ON t_user_file FOR EACH ROW
BEGIN
  UPDATE t_file SET f_count = f_count - 1 WHERE t_file.f_id = OLD.f_id;
  DELETE FROM t_file WHERE f_count = 0 AND t_file.f_id = OLD.f_id;
END;
```

> 业务代码删完关系后会**再查一次 `t_file`**，查不到就 `unlink` 磁盘文件 —— 触发器负责元数据，代码负责物理文件，两者配合实现"最后一个用户删掉后文件才真正消失"。

## 10. 核心机制剖析

### 10.1 秒传（MD5 去重 + 引用计数）

1. 客户端上传前对文件全量计算 MD5（`getFileMD5`，1KB 分块读，边读边 `md5.update`）；
2. `UPLOAD_FILE_RQ` 带上 `md5`；
3. 服务端先 `select f_id from t_file where f_MD5=? and f_state=1`：
   - **命中** → 只往 `t_user_file` 插一条关系（触发器自动 +1），回 `QUICK_UPLOAD_RS`，**一个字节都不传**；
   - 未命中 → 走正常上传流。
4. 唯一存储：磁盘文件名就是 MD5，多个用户指向同一个 `f_id`、同一份物理文件。

### 10.2 断点续传

**任务标识**：客户端生成 `timestamp = hhmmsszzz`；服务端内存 map 的 key 为 `userid * 1000000000 + timestamp`（`getNumber()` 返回值）。

| 方向 | 触发 | 协议 | 服务端动作 |
|---|---|---|---|
| 上传 | 客户端暂停后点继续（内存任务已丢） | `CONTINUE_UPLOAD_RQ` | 查/建 `FileInfo` → `lseek(fd,0,SEEK_END)` 得到已写入位置 → 回 `pos` |
| 下载 | 客户端暂停后点继续 | `CONTINUE_DOWNLOAD_RQ` | 查/建 `FileInfo`（不命中就回查数据库重建）→ `lseek(fd,pos,SEEK_SET)` → 直接回第一个数据块 |

### 10.3 上传数据流（客户端视角）

```
slot_uploadFile
  ├─ 算 md5、取 size/time、fopen("rb")、生成 timestamp
  ├─ map[timestamp] = info
  └─ 发 UPLOAD_FILE_RQ
        ↓ 收 UPLOAD_FILE_RS（拿到 fileid）
  ├─ 写 SQLite(t_upload)、界面插入"上传中"
  └─ 发 FILE_CONTENT_RQ（fread 4096）
        ↓ 收 FILE_CONTENT_RS
  ├─ pos += len → emit 进度信号
  ├─ pos >= size ? 关文件、删缓存、刷新列表
  └─ 否则继续 fread 下一块…
```

### 10.4 设计模式应用

| 模式 | 位置 | 作用 |
|---|---|---|
| 单例 | `CKernel::GetInstance`、`TcpKernel::GetInstance` | 全局唯一核心，静态局部变量实现 |
| 中介者 | `INetMediator` / `TcpClientMediator` / `TcpServerMediator` | 网络层只抛 `SIG_ReadyData`，业务层只连信号，彻底解耦 |
| 模板方法 | `INet` 定义流程骨架（Init/Send/Recv），子类实现 | TCP/UDP 复用 |
| 策略/查表 | `PFUN m_netPackMap[100]` | 用函数指针数组代替 `switch`，新增协议只加一行映射 |
| 模板类 | `MyMap<K,V>` | 线程安全 map 复用 |
